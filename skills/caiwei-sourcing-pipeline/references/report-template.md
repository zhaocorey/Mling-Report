# 寻源增量报告模板

生成报告时严格按以下结构输出，文件名为 `sources_reports/YYYY-MM-DD.md`。

## 报告结构

```markdown
# 多语言数据集寻源增量报告

**日期**: YYYY-MM-DD
**调研团队**: 小蜜蜂🐝 (寻源) + 语教授🎓 (报告)
**上次运行**: YYYY-MM-DD HH:MM
**本次增量**: N 个数据集（M 新增 / K 更新）

---

## 🆕 新增数据集

> 首次出现在基线中的数据集

### [数据集名称]
- **链接**: URL
- **语言覆盖**: 语言列表
- **数据规模**: 规模描述
- **许可协议**: 许可证
- **类别**: 预训练 / 微调 / 评估
- **发现日期**: YYYY-MM-DD
- **最后更新**: YYYY-MM-DD
- **时效性**: 高 / 中 / 低
- **描述**: 简要描述
- **优缺点分析**:
  - ✅ 优势 1
  - ✅ 优势 2
  - ⚠️ 注意事项
- **推荐优先级**: ⭐⭐⭐⭐⭐ — 评价
- **推荐判断**: ✅/⚠️/❌ 推荐说明

（重复每个新增数据集）

---

## 🔄 更新数据集

> 已知数据集发生版本/规模/语言覆盖变化

### [数据集名称]
- **变更摘要**: 具体变更内容
- **上次版本**: vX.X → **当前版本**: vY.Y
- **变更影响**: 对推荐优先级的影响分析

（重复每个更新数据集）

---

## 📊 时效性分析

### 基线健康度
| 指标 | 数值 |
|------|------|
| 基线总数 | N 个 |
| 高时效（3月内） | N 个 |
| 中时效（3-12月） | N 个 |
| 低时效（>12月） | N 个 |
| 陈旧（>6月未更新） | N 个 |

### 本次变化
- 新增数据集对 Top 10 的影响
- 更新数据集对推荐优先级的调整
- 需关注的陈旧数据集（建议降级或移除）

---

## 💡 新增推荐

### Top 10 更新建议
如有新增数据集值得加入 Top 10，明确标注：
1. **新数据集名称** — 推荐理由 + 建议替换哪个现有数据集
2. 如无变化，注明"本次 Top 10 无调整"

---

*报告由语教授🎓基于小蜜蜂🐝的增量寻源结果撰写。*
```

## 数据集 JSON 记录格式

`bee_sources.json` 和 `bee_sources_incremental.json` 中每条数据集的标准格式：

```json
{
  "name": "数据集名称",
  "url": "https://...",
  "languages": ["en", "zh", "ja"],
  "size": "数据规模描述",
  "license": "许可协议",
  "category": "预训练 | 微调 | 评估",
  "description": "简要描述",
  "discovered_date": "YYYY-MM-DD",
  "last_updated": "YYYY-MM-DD",
  "release_version": "vX.X",
  "timeliness_score": "高 | 中 | 低"
}
```

`bee_sources.json` 顶层结构：

```json
{
  "search_date": "YYYY-MM-DD",
  "search_summary": "寻源摘要",
  "sources": [ ... ]
}
```
